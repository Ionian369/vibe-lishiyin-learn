# PRD · 教务器材预约系统

> 版本：v1.0（2026-10-07，吸收 Q1–Q13 拍板结果）
> 一句话：让「谁先约到器材」从群里吵架，变成系统里一条 409。

## 1. 做什么、给谁、怎么算成功

- **做什么**：无登录的班内器材预约工具。用户填姓名，浏览器材卡片，选「日期 + 上午/下午」提交预约；同一器材同日期同时段只能被约走一次；可查自己的历史、取消自己的预约。
- **给谁**：借器材的同学/社团干事（约、查、取消）；管器材的课代表（不再手工核对共享表格，冲突由系统裁定）。
- **怎么算成功**：演示时连点两次「预约」，第二次被 409 拒绝且红字提示具体到「器材 + 日期 + 时段」——冲突拒绝是这个系统的灵魂。次级成功标志：约错了不用找管理员改库，本人一秒取消。

### 2.2 本期明确不做（二期池）

- 登录/鉴权（Q2：班内互信场景，姓名即身份是已声明的已知边界；`user_name` 字段已预留，二期接学号+口令不改表）
- 库存数量（Q4：唯一索引模型 = 单件贵重设备定位，正好成立）
- 节次时段扩展（Q5：period 为字符串存储，二期扩展做成配置而非硬编码）
- 分页、审批流、消息通知、管理员视角

### 2.3 已知行为（不是 bug，明确接受）

- 一人可在同一时段预约多个器材（借投影仪 + 话筒办同一场活动是合理场景）——Q7
- 身份仅是 localStorage 里的姓名，任何人填他人名字可查看/冒用——Q2 已声明的边界

## 4. 接口契约

统一响应 `Result`：`{code, message, data}`；code=0 成功，非 0 与 HTTP 状态码一致。开发期前端经 Vite 代理同源访问。

| 方法 | 路径 | 入参 | 出参 | 错误码 |
|---|---|---|---|---|
| GET | `/api/ping` | 无 | `{"status":"ok"}`（裸 JSON，Result 契约例外） | — |
| GET | `/api/devices` | 无 | `Result<data:[{id, name, description}]>` | — |
| POST | `/api/reservations` | Body：`{deviceId:int 必填, date:"YYYY-MM-DD" 必填且今天起 14 天内, period:"上午"\|"下午" 必填, user:string 必填且 ≤50 字}` | `Result<data:{id, deviceId, deviceName, date, period, userName, createdAt, status}>`（status 为 M4 新增） | 400 参数校验失败（第一条校验错误/超 14 天【M2】/姓名超长【M5】）；404 器材不存在；409 时段冲突 |
| GET | `/api/reservations` | Query：`user`（必填，trim 后精确匹配） | `Result<data: ReservationVO[]>`，按 createdAt 倒序，上限 200 条【M6】 | 400 缺 user（返回 Result 结构【M5】） |
| GET | `/api/reservations/stats` | Query：`user`（必填） | `Result<data:{"count":long}>`（累计口径） | 400 缺 user（返回 Result 结构【M5】） |
| DELETE | `/api/reservations/{id}` | Query：`user`（必填，须与记录归属一致） | `Result<Void>`（data=null）【M3 新增】 | 400 缺 user；403 只能取消本人预约；404 记录不存在 |

错误码语义：`0` 成功 · `400` 参数不合法 · `403` 非本人操作（M3 引入）· `404` 资源不存在 · `409` 时段冲突（文案含「器材在 日期 时段 已被预约，请更换时段」）。

## 5. 成功指标（演示脚本 90 秒）

1. 打开首页 → 三张器材卡片（3 秒可判）
2. 保存姓名「李诗滢」→ 历史与次数出现
3. 预约投影仪 3 天后上午 → 绿色成功，次数 +1【M3 后可续演：行内取消 → 次数 -1 → 换名再约同一时段成功】
4. 再约同一时段 → 红色 409，文案具体到器材/日期/时段，弹窗不关
5. 日期选 15 天后 → 选择器禁选；curl 直调 → 400【M2】
6. curl `/api/ping` → `{"status":"ok"}`
