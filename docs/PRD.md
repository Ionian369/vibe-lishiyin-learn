## 1. 一句话定位

让「谁先约到器材」从群里吵架，变成系统里一条 409——同一器材 + 同一日期 + 同一时段，只有一个人能约成功。

## 2. 给谁用（两类真实用户）

| 用户 | 场景 | 今天怎么过 | 用了之后 |
|------|------|-----------|---------|
| **借器材的人**（普通同学 / 社团干事） | 借投影仪、音响、无线话筒办活动 | 班群接龙，谁先约到全凭记忆，到现场才发现设备被人拿走 | 打开页面选器材选时段，约没约上当下见分晓 |
| **管器材的人**（课代表 / 教务器材管理员） | 每周核对预约登记 | 手工核对共享表格，两个班约了同一台投影仪现场扯皮 | 冲突在提交那一刻被系统拦下，理由具体到器材/日期/时段 |

## 3. 本期范围：恰好三个功能

| # | 功能 | 验收口径（能演示出来的才算数） |
|---|------|------------------------------|
| F1 | **浏览**器材卡片 | 首屏三张卡片（投影仪/音响/无线话筒），含名称与用途说明 |
| F2 | **提交**预约并被裁定 | 选日期（今天~+14 天）+ 时段（上午/下午）提交；同一器材同一时段第二次提交返回 409，弹窗持久展示冲突原因，改选即可重试 |
| F3 | **查询**我的预约历史 | 填姓名即出列表（器材/日期/时段/状态/提交时间），成功次数实时累计；**本人可取消**自己的预约 |

> F2/F3 的增强项（14 天窗口、状态后端下发、取消预约）见任务看板 P0，Day3 起实施。

## 4. 明确不做（本期红线，摘自 AGENTS.md §7）

登录（学号+口令）、库存数量、节次时段、分页、器材管理界面——全部进二期需求池，本期一行代码不写。理由见 AGENTS.md 红线表。

## 5. 怎么算成功（可量化验收标准）

1. **功能验收**：三件套任务看板 P0 全部完成，每项走双通道验收（浏览器全路径 + curl 错误码路径）
2. **冲突演示**：连点两次同一时段预约——第一次绿色成功、第二次红色 409 且文案具体到「{器材}在 {日期} {时段} 已被预约」
3. **数据可靠**：重启后端预约记录不丢（H2 落盘）；并发双击提交不会产生两条同槽预约（唯一索引兜底）
4. **边界一致**：「待使用/已结束」状态与日期合法性均由后端服务器时间裁决，前端只渲染
5. **交付完整**：每日收工四步全绿（反思件 / 署名 commit / dayN tag / 自查脚本），第 10 天可公开演示

## 6. 信任模型与已知边界

- **姓名即身份**：无登录无鉴权，姓名存浏览器 localStorage，后端按 `user_name` 精确匹配。班内互信场景下接受；冒用风险是已声明边界，非疏漏。
- **单件资源**：一个器材 = 一份资源，无"台数"概念。
- 演示时主动向观众说明以上两条边界（电梯稿审题三问的标准动作）。
