# 技术方案 · 教务器材预约系统

> 版本：v1.0（2026-10-07，与 docs/PRD.md v1.0 对齐）
> 本文 = 现状架构 + 拍板后目标态设计。凡标【M#】的改动项对应 docs/任务看板.md 任务块，未标注的均为已实现现状。

## 1. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue3 + Element Plus + Vite | 组件化 + 表单/弹窗开箱即用；`/api` 代理规避跨域 |
| 后端 | Spring Boot 3 + Spring Data JPA | Controller/Service/Repository 分层，对应课程结构 |
| 数据 | H2 文件库（`jdbc:h2:file:./data/reservation;AUTO_SERVER=TRUE`） | 零安装、落盘重启不丢、UNIQUE 索引兜底并发 |
| HTTP 客户端 | axios（10s 超时，响应拦截解包 Result） | 错误文案只展示后端 message，前端不编造 |

不引入新依赖、新中间件（Redis/消息队列等一律不用）——班内量级用不上，是范围失控的典型入口。

## 2. 架构与数据流

```
浏览器 :5173
  └─ Vue3 SPA（ReservationView 单页）
       └─ axios baseURL=/api
            └─ Vite devServer proxy → http://localhost:8080/api
                 └─ Controller（参数校验 / Result 封装）
                      └─ Service（业务规则：冲突、14 天上限、归属校验、状态计算）
                           └─ Repository（Spring Data JPA）
                                └─ H2 文件库（唯一索引 uk_reservation_slot 兜底并发）
```

- 开发期同源代理，CORS 仅作直连兜底【M8：prod 同源托管后删除 CORS 配置】。
- 前端不做业务裁定：冲突原因、状态、校验文案全部以后端为准。

## 3. 数据模型

### device（器材字典）
| 列 | 类型 | 约束 |
|---|---|---|
| id | BIGINT | PK，自增 |
| name | VARCHAR(50) | NOT NULL |
| description | VARCHAR(200) | |

### reservation（预约记录）
| 列 | 类型 | 约束 |
|---|---|---|
| id | BIGINT | PK，自增 |
| device_id | BIGINT | NOT NULL，逻辑关联 device |
| reservation_date | DATE | NOT NULL |
| period | VARCHAR(10) | NOT NULL，取值「上午/下午」 |
| user_name | VARCHAR(50) | NOT NULL，预留二期学号登录 |
| created_at | TIMESTAMP | NOT NULL，@PrePersist 填充 |

唯一索引 `uk_reservation_slot(device_id, reservation_date, period)`——同器材同日期同时段仅一条，**并发安全的最终裁判，任何改动不得绕过或删除**。

### 初始化策略
- 现状：`data.sql` 每次启动 `DELETE FROM device` + 重插三件套。
- 目标态【M1】：删除 `data.sql`，改为 `DataInitializer implements ApplicationRunner`——`deviceRepository.count() == 0` 时才插入投影仪/音响/无线话筒。效果：已有库不再被重置，为二期器材管理留活路。`application.yml` 中 `spring.sql.init.*` 配置随之删除。
- 预约记录不做初始化，空库即空列表。

## 4. 后端模块与关键设计

```
backend/src/main/java/com/school/reservation/
├── controller/   PingController、DeviceController、ReservationController（薄，只做参数校验与 Result 封装）
├── service/      ReservationService（业务规则唯一属地）
├── repository/   DeviceRepository、ReservationRepository（Spring Data 接口查询）
├── entity/       Device、Reservation（JPA 实体 + 约束）
├── dto/          Result、ReservationRequest、ReservationVO、DeviceVO
├── exception/    BizException、GlobalExceptionHandler
└── config/       WebConfig（CORS，dev 限定【M8】）
```

### 4.1 三层冲突防护（核心，已实现）
1. Service 前置查询 `existsByDeviceIdAndDateAndPeriod` → 快速失败；
2. DB 唯一索引 `uk_reservation_slot` → 拦下并发穿透；
3. `DataIntegrityViolationException` 被 Service 捕获转 `BizException(409)`，文案具体到「器材在 日期 时段 已被预约，请更换时段」。

### 4.2 预约窗口校验【M2】
- 后端：`ReservationService.create()` 内校验 `date > LocalDate.now().plusDays(14)` → `BizException(400, "最多可提前 14 天预约")`；过去日期仍由 `@FutureOrPresent` 拦截。
- 前端：`ReservationDialog.disabledDate()` 同步禁选「今天之前 || 今天+14 之后」，两端口径一致，后端为准。

### 4.3 状态计算【M4】
- `ReservationVO` 增加 `String status` 字段；Service 组装 VO 时按**服务器时间** `LocalDate.now()` 判定：`date < today → "已结束"`，否则 `"待使用"`。
- 前端删除本地 `reservationStatus()` 函数，直接渲染 `row.status`——边界只允许一个裁判（Q9 拍板）。
- 同任务块内把次数标签文案改为「累计预约成功 N 次」（Q8：实现即口径，逻辑不动）。

### 4.4 取消预约【M3】
- 接口：`DELETE /api/reservations/{id}?user=xxx`。
- Service 逻辑（顺序固定）：
  1. `findById` 不存在 → `BizException(404, "预约记录不存在")`；
  2. `userName` 与 `user` 参数 trim 后不一致 → `BizException(403, "只能取消本人的预约")`（与现有「姓名即身份」信任模型自洽）；
  3. 一致则 `delete`，返回 `Result<Void>`。
- 403 为新错误码，语义「非本人操作」，加入错误码表。
- 前端：历史表格加「取消」操作列 → `ElMessageBox.confirm` 二次确认 → 调接口 → 成功后 toast + 刷新列表与次数。不限制已结束记录取消（仅清理记录）。

### 4.5 错误契约统一【M5】
- `ReservationRequest.user` 加 `@Size(max = 50, message = "姓名不能超过 50 个字")`——超长自然落 400，而非穿透到 500。
- `GlobalExceptionHandler` 新增 `MissingServletRequestParameterException` 处理 → `Result.fail(400, "缺少必填参数：" + 参数名)`，消除「400 但响应体非 Result」的不一致。
- `/api/ping` 保留裸 JSON：健康检查惯例，作为契约唯一例外注明于此。
- 兜底 `Exception` 处理器暂不加（避免吞掉真实错误，保持简单）。

### 4.6 查询护栏【M6】
- `findByUserNameOrderByCreatedAtDesc` 改为带 `Pageable`：`PageRequest.of(0, 200)`（按 createdAt 倒序不变）。班内量级到不了分页需求，LIMIT 200 是零成本防御；正式分页排二期。

## 6. Profile 与部署【M8】

| 配置 | dev（默认，现状保持） | prod（部署前收紧） |
|---|---|---|
| H2 console `/h2-console` | 开 | **关** |
| CORS `/api/**` 全放行 | 保留（直连兜底） | **删除**（同源后无存在必要） |
| 前端 | `npm run dev`（:5173 代理） | `vite build` 产物由 Spring Boot 静态托管或同源静态服务器 |
| 激活方式 | 默认 | `--spring.profiles.active=prod` |

实现：拆 `application-dev.yml` / `application-prod.yml`；`WebConfig` 的 CORS 注册加 `@Profile("dev")`。
