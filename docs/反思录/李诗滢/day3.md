## 反思区（今天指挥 AI 干成了什么 / 坑在哪）

实验三的主线是"核心功能闭环 ×3 + 小步提交"。按手册"任务拆解后逐个喂"，我把看板 D3-1/D4-1/D4-2 三张任务卡逐张推进，每条功能线走完固定循环：任务卡 → @相关文件 → AI 实现 → 本地跑 → diff 审 → commit。三条功能线（取消预约 / 14 天窗口 / status 后端下发）全部前后端闭环，外加把另一会话遗留的分页功能验证后独立提交——今天 master 上共 4 个功能提交，commit 历史能清晰看出"一个功能一个提交"的颗粒度。

坑两处：① 取消预约验收脚本造测试数据撞了昨天的预约（409），导致四条断言全走偏——返工改遍历找空槽位后全绿；② 14 天窗口前端第一版 disabledDate 边界多禁了一天（+14 当天也被禁），与验收标准③矛盾——返工对齐成"+14 当天可约、+15 起禁选"。两个坑都不是功能 bug，都是**验收口径的边界细节**，正好印证知识要点"你产出的质量上限 = 你的验收能力"。
