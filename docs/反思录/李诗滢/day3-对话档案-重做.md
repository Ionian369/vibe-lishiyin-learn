## 档案二：浏览器验收卡死两次——造数改走 API（返工 2 次 → 通过）

**提问（任务）**：功能 A 完成后按 AGENTS.md §6 T1 双通道验收，浏览器通道要走"预约 → 取消"完整用户路径。

**第一次执行**：浏览器代理打开 :5173 正常、填名保存正常，但在 Element Plus 日期面板翻到 12 月时反复报"元素不可见 / 引用过期"，预算耗尽，步骤 3 起 BLOCKED。

**返工 1**：续用代理，改为直接在日期框键入 `2026-12-30`（不碰日历面板）——又卡在"面板遮挡提交按钮"，第二次预算耗尽。

**返工 2（换策略）**：意识到价值错位——浏览器要验的是**取消链路**，不是造数。改用 curl 直接造两条 `user=测试A同学` 的预约（id=194/195），浏览器只走：填名 → 见 2 条 → 取消 1 条。

**通过**：
```
历史 2 条 + 「累计预约成功 2 次」
取消(上午) → 行消失、次数 2→1、toast「已取消该预约」
```
（换名取消场景由 curl 通道覆盖：UI 上历史按姓名过滤，"取消他人"在界面上不可达，403 的真实防护对象是直调接口——这正是 curl 通道存在的意义。）

**收获**：UI 自动化验收里"造数"和"验交互"要拆开——数据走 API 一次到位，浏览器预算只花在只有浏览器能验的事情上。

## 档案三：两个通道打架——"今天被禁选"误报（返工 1 次 → 通过）

**现象**：功能 B 验收，浏览器代理报告：10-21 可选 ✅、10-22 起灰 ✅、但"今天 10-07 被标 next-month disabled"——与 curl 实测直接矛盾（今天 10-07 的预约 id=226 刚成功创建）。

**返工动作**：不轻信 DOM 报告，带着矛盾证据复核三步：先看面板年月标题（排除翻错月）→ 查 10-07 的 class 明细 → 实际点击它。

**通过**：面板就是 2026 October；10-07 class = `available today current`（无 disabled）；点击后输入框成功填入 `2026-10-07`。上轮"next-month disabled"为代理对 DOM 的解读误判。

**收获**：两个验收通道结论打架时，别急着改代码——找"可执行结果"当裁判（点击能否填上、请求能否成功）。DOM 类名可能读串，行为不会撒谎。

## 档案四：回归用例撞上自己刚上线的功能（返工 1 次 → 通过）

**提问（任务）**：M5 错误契约验收——50 字姓名（边界值）应可正常约成功（51 字才拒）。

**第一次执行**：POST 50 字姓名 + 日期 `2026-12-31` → 返回 400「预约日期最多提前 14 天」——既不是预期的 200，也不是姓名报错。

**返工分析**：不是 bug。错误文案本身就是证据：姓名校验在 DTO 层先通过（说明 50 字合法），进 Service 后撞上同一天刚上线的 14 天窗口——**回归用例的日期参数抄了旧数据**（12-31 在窗口外）。

**返工动作**：日期换窗内空槽位 `2026-10-21` 下午重测。

**通过**：code=0，id=257，50 字姓名完整入库（与 DB 列宽 VARCHAR(50) 严丝合缝）。

**收获**：一天连做多个功能时，回归用例参数不能顺手抄旧值——每条用例都要过一遍"新校验是否影响这条路径"；错误文案是免费的调试信息，先读懂它再动手。
