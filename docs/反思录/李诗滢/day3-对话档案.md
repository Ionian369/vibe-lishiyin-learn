## 档案一：取消预约的验收脚本返工（返工 1 次 → 通过）

**提问（我）**：
> 按任务卡 D3-1 实施取消预约（仅本人）：后端 DELETE /api/reservations/{id}?user=，404/403 双错误路径，前端两处历史列表行内取消按钮，二次确认。完成后 curl 双通道验收。

**AI 第一次执行**：
- 后端 Service 加 `cancel()`：findById → 404「预约记录不存在」；姓名不匹配 → 403「只能取消自己的预约」；delete
- Controller 加 `@DeleteMapping("/{id}")`；前端 api 加 `cancelReservation()`，两个视图加操作列
- 验收脚本随手造了一条"明天上午 + 投影仪"的测试预约

**返工原因**：
- 造测试数据直接 409——**昨天测试约过同一个槽位**，`$created` 为空导致后续四条断言全部走偏（id 空串 → 全 404，验收无效）。这不是功能 bug，是验收脚本的测试数据撞库。

**返工动作**：
- 验收脚本改为**遍历未来 3–14 天 × 上午/下午找空槽位**再造数据

**通过**（四路径全绿）：
```
CREATED id=129 (2026-10-10 下午)
② 他人取消 → 403（只能取消自己的预约）
③ 不存在 → 404（预约记录不存在）
① 本人取消 → code=0
④ 复删 → 404
```

**收获**：验收脚本也要防"数据依赖"——用固定槽位造数早晚撞库，改遍历找空位一次到位。

## 档案二：14 天窗口的边界口径确认（返工 1 次 → 通过）

**提问（我）**：
> 按任务卡 D4-1 实施预约窗口：前端 disabledDate 禁 +15 天起，后端 Service 校验 date > today+14 → 400「预约日期最多提前 14 天」。

**AI 第一次执行**：
- 前端 disabledDate 直接写 `date > today+14` 禁选——**边界多禁了一天**：+14 天当天也被禁，与任务卡验收③"今天与 +14 天当天均可约"矛盾
- 后端校验 `isAfter(today+14)` 本身正确（+14 当天放行）

**返工原因**：
- 前后端口径必须逐字对齐：后端是"超过 +14 才拒"（isAfter），前端禁选边界应是"+14 之后"（`>= today+15`）。第一版前端按直觉写成了"+14 起"。

**返工动作**：
- disabledDate 改为 `date >= today + (14+1)`，即 +14 当天可选、+15 起禁选，并注释"与后端窗口校验同口径，后端为准"

**通过**（curl 双路径）：
```
② +15天 → 400（预约日期最多提前 14 天）
③ +14天当天 → code=0（可约）
```

**收获**：窗口类需求的"边界日归属"要写进任务卡验收标准（③当天可约），否则前后端两个 `>` `>=` 各写各的，演示时准翻车。
